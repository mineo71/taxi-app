# Архітектура

Архітектура описана за моделлю **C4** — чотири рівні деталізації від загального погляду ззовні до внутрішньої будови. Кожен наступний рівень збільшує **один** елемент попереднього, як масштаб на карті. Кожен рівень призначений для своєї аудиторії, тому одна детальна схема не замінює чотири різні.

| Рівень | Що показує | Для кого | Документ |
|---|---|---|---|
| C1 — System Context | Система однією коробкою, її користувачі та зовнішні сервіси. Без технологій | Замовник, бізнес | [c1-system-context.md](c1-system-context.md) |
| C2 — Containers | Окремо запущені застосунки, сервіси та сховища, кожен зі своєю технологією | Архітектор, вся команда | [c2-containers.md](c2-containers.md) |
| C3 — Components | Начинка одного контейнера — сервісу замовлень | Розробники сервісу | [c3-order-service.md](c3-order-service.md) |
| C4 — Code | Класи й методи компонента | — | Не малюється: код змінюється щодня, і діаграма застаріває швидше, ніж її встигають оновити |

## Діаграми

- Діаграми в Markdown (Mermaid) відображаються прямо на GitHub у файлах рівнів.
- Редаговані діаграми draw.io: [`diagrams/taxi-c4-model.drawio`](diagrams/taxi-c4-model.drawio) — три сторінки C1, C2, C3. Відкривається на [app.diagrams.net](https://app.diagrams.net) через *File → Open From → Device*.

### Правила оформлення

1. **Заголовок** — тип діаграми, рівень і назва системи.
2. **Легенда** — що означає кожен колір і форма.
3. **Повний підпис елемента** — назва, тип у квадратних дужках, технологія, одне речення опису.
4. **Підписана стрілка** — що саме відбувається і яким протоколом. Напрямок показує залежність: хто кого викликає.
5. **Без нерозшифрованих скорочень** — діаграма читається сама по собі.

### Легенда

| Колір | Значення |
|---|---|
| Темно-синій | Людина (Person) |
| Синій | Наша система або її контейнер |
| Світло-синій | Компонент усередині контейнера |
| Сірий | Зовнішня система |
| Пунктирна рамка | Межа системи або контейнера |
