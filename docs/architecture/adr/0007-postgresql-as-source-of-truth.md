# ADR-0007: PostgreSQL як основне сховище

- **Статус:** Прийнято
- **Дата:** 2026-10-15

## Контекст

Користувачі, водії, поїздки, тарифи й платежі — пов'язані дані, для яких важливі транзакції та цілісність: поїздка не може бути оплачена двічі, тариф не може зникнути посеред поїздки. Потрібне резервне копіювання з RPO до 15 хвилин і RTO до 1 години ([NFR-10](../../requirements/non-functional.md)). Дані зберігаються в Україні або ЄС ([CON-8](../../requirements/constraints.md)).

## Рішення

**PostgreSQL** — джерело істини для користувачів, поїздок, тарифів і платежів. Доступ з коду — через репозиторії (Prisma) у кожному сервісі.

## Розглянуті альтернативи

- **MongoDB** — гнучка схема не дає переваг для чітко структурованих даних, слабші гарантії зв'язків між сутностями.
- **MySQL** — прийнятний варіант, але PostgreSQL має PostGIS для геозапитів в аналітиці та кращу підтримку JSON-полів.

## Наслідки

**Позитивні:**

- ACID-транзакції для поїздок і платежів.
- Безперервне архівування журналу транзакцій дає RPO в межах хвилин.
- Репліки для читання розвантажують аналітику ([FR-34](../../requirements/functional.md)).

**Негативні:**

- Часто змінювані дані (позиції водіїв) сюди не пишуться — для них окреме сховище ([ADR-0008](0008-redis-geo-index-for-driver-positions.md)).
