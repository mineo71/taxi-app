# Нефункціональні вимоги

Нефункціональні вимоги описують, **як добре** працює система. Кожна вимога сформульована з вимірюваним показником і способом перевірки — інакше її неможливо перевірити.

| Код | Категорія | Вимога | Як перевіряємо |
|---|---|---|---|
| NFR-1 | Продуктивність | Пошук водія до 5 секунд у 95% випадків | Метрика «час до призначення водія», p95 у моніторингу |
| NFR-2 | Продуктивність | Позиція водія оновлюється кожні 2–5 секунд | Інтервал подій позиції в сервісі реального часу |
| NFR-3 | Продуктивність | Відповідь API до 300 мс (p95) | Навантажувальний тест, метрики шлюзу |
| NFR-4 | Продуктивність | Холодний старт застосунку до 3 секунд | Вимірювання на бюджетному Android-пристрої |
| NFR-5 | Масштабованість | Витримує пік у 5 разів вище середнього без деградації | Навантажувальний тест з п'ятикратним середнім навантаженням |
| NFR-6 | Масштабованість | Горизонтальне масштабування, нові міста без зміни архітектури | Нове місто додається конфігурацією тарифів і зон |
| NFR-7 | Доступність | Uptime не нижче 99,9% (≈ 43 хв простою на місяць) | Зовнішній моніторинг доступності |
| NFR-8 | Надійність | Активна поїздка не втрачається при збої застосунку чи зв'язку | Тест: примусове закриття застосунку та вимкнення мережі під час поїздки |
| NFR-9 | Надійність | Коректна робота при слабкому інтернеті, офлайн-кеш, повторні запити | Тест в емуляції 3G і втрати пакетів |
| NFR-10 | Надійність | Резервне копіювання: RPO до 15 хвилин, RTO до 1 години | Регулярне тестове відновлення з резервної копії |
| NFR-11 | Безпека | Весь трафік через HTTPS/TLS 1.2+, certificate pinning | Сканування TLS-конфігурації, тест на перехоплення трафіку |
| NFR-12 | Безпека | Платежі через провайдера за PCI DSS, повні дані карток не зберігаються | Перевірка схеми БД: лише токени карток |
| NFR-13 | Безпека | Токени з обмеженим терміном, rate limiting, захист від перебору коду | Тест: серія невдалих спроб коду блокує вхід |
| NFR-14 | Безпека | Розмежування доступу до адмінки за ролями, логування дій | Перевірка прав ролей і журналу аудиту |
| NFR-15 | Відповідність | Закон України «Про захист персональних даних», GDPR для ЄС | Політика конфіденційності, реєстр обробки даних |
| NFR-16 | Приватність | Маскування номерів, обмежений термін зберігання геолокації | Номери не видно у застосунках; автоматичне видалення старих треків |
| NFR-17 | Відповідність | Фіскалізація та видача чеків | Чек формується для кожної оплати |
| NFR-18 | Зручність | Базове замовлення не більше ніж за 3–4 дії | Юзабіліті-тестування на прототипі |
| NFR-19 | Доступність | WCAG 2.1 AA: контраст, VoiceOver і TalkBack, масштабування шрифтів | Автоматичний аудит і ручна перевірка зчитувачами екрана |
| NFR-20 | Зручність | Темна тема | Перевірка всіх екранів у темній темі |
| NFR-21 | Локалізація | Українська та англійська з можливістю додати інші | Усі рядки винесені в ресурси локалізації |
| NFR-22 | Сумісність | iOS 15+ та Android 8+, стабільність на бюджетних пристроях | Тестова матриця пристроїв |
| NFR-23 | Сумісність | Помірне енергоспоживання при фоновому GPS | Вимірювання витрати заряду за годину роботи водія на лінії |
| NFR-24 | Підтримуваність | Модульна архітектура, CI/CD, автотести критичних сценаріїв | Пайплайн CI запускає тести на кожну зміну |
| NFR-25 | Спостережуваність | Централізоване логування, моніторинг, алерти, трасування | Кожен запит простежується через усі сервіси за ідентифікатором |
| NFR-26 | Підтримуваність | Feature flags і поетапне викочування оновлень | Нова функція вмикається для частини користувачів |

## Особливості для України

Окремо варто уваги NFR-9 і NFR-10: відключення електроенергії та перевантаження мобільних мереж роблять стійкість до слабкого зв'язку не теоретичною, а щоденною вимогою.
